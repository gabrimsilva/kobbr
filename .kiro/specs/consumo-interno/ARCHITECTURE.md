(RLS)\n\n```\nUsuário de EST-A\n├─ Vê apenas: internal_consumptions.estabelecimento_id = EST_A\n├─ INSERT apenas em: EST_A\n└─ UPDATE/DELETE: Bloqueado (imutável)\n\nUsuário de EST-B\n├─ Vê apenas: internal_consumptions.estabelecimento_id = EST_B\n├─ INSERT apenas em: EST_B\n└─ UPDATE/DELETE: Bloqueado (imutável)\n\n❌ Usuário de EST-A NÃO consegue:\n   ├─ Ver dados de EST-B\n   ├─ INSERT em EST-B\n   └─ Alterar consumos (UPDATE/DELETE)\n```\n\n### Atomicity (All-or-Nothing)\n\n```\nSe qualquer operação falha:\n\nINSERT sales → OK\nINSERT internal_consumptions → OK\nUPDATE stock_items → FALHA (stock insuficiente)\n\nResultado: TODA A TRANSAÇÃO É REVERTIDA\n\n✓ Nada foi registrado\n✓ Stock não mudou\n✓ Banco fica consistente\n✓ Usuário recebe erro com mensagem clara\n```\n\n---\n\n## 📊 Performance\n\n### Índices Otimizados\n\n```\nIdx 1: (estabelecimento_id, consumed_at DESC)\n├─ Busca rápida por estabelecimento\n├─ Ordenação já otimizada\n└─ Lookup de período eficiente\n\nIdx 2: (sale_id) UNIQUE\n├─ Lookup O(1) para venda\n├─ Garante unicidade\n└─ FK relationship rápido\n\nIdx 3: (created_by)\n├─ Queries por usuário criador\n└─ Auditoria rápida\n\nResultado:\n✓ < 500ms para queries com 1000+ registros\n✓ Escalável para anos de histórico\n```\n\n### Queries Eficientes\n\n```\nGranularidade Dia (365 registros):\n- GROUP BY DATE_TRUNC('day', consumed_at)\n- ~50-100ms (com índice)\n\nGranularidade Semana (52 registros):\n- GROUP BY DATE_TRUNC('week', consumed_at)\n- ~100-150ms\n\nGranularidade Mês (12 registros):\n- GROUP BY DATE_TRUNC('month', consumed_at)\n- ~50-100ms\n\nTodas < 500ms ✓\n```\n\n---\n\n## 🎯 Componentes Principais\n\n### Frontend\n- `ModalFinalizarPedido.tsx` - UI com checkbox\n- `useConsumoInterno.ts` - Hook de lógica\n-
